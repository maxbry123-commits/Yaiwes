PRINCIPIO ARQUITECTÓNICO
Hay cuatro componentes separados:
AGENDA: determina cuándo.
PERFIL: determina qué información se puede consultar.

LA LLM SOLO SE ACTIVA CUANDO UNA TAREA NECESITA RAZONAMIENTO.
Hay tres reglas fundamentales:
Ningún agente permanece activo esperando su siguiente tarea.
Ningún agente tiene acceso automático al contexto de los pasos posteriores.
Ningún agente decide por sí mismo qué tarea debe ejecutarse después.
El motor determinista conserva el control de todo el ciclo.

# 0. DEFINICIÓN RAÍZ

YAIWES NO ES UN AGENTE.

YAIWES es un sistema de software determinista compuesto por:
CORE + MATRIX + TASK-OS + MEMORIA + MICROSERVICIOS + EJECUTORES TEMPORALES.

Regla principal:
.
SOFTWARE CONTROLA
→ TRIGGER ACTIVA
→ EJECUTOR TRABAJA
→ VERIFICADOR REPORTA
→ SOFTWARE CAMBIA ESTADO

La LLM nunca gobierna el sistema.

## 1. DEFINICIONES OBLIGATORIAS

CORE = software determinista de control.

MATRIX MAXBRY AGI = plano central que registra estados, tickets, índices, permisos, triggers y resultados.

TASK = ticket.

WORKFLOW YAIWES = state machine ejecutable.
NO es un loop de agente.

TASK-OS = plantilla ejecutable de una tarea.

MICROKERNEL = compilador aislado que:
PLAN + TEMPLATE → TASK-OS..

ASK COUNCIL = departamento aislado de arquitectos/ingenieros que diseña PLAN.json.

INPUT SHARK = investigación/evidencia previa.

MEMORY = base de datos + biblioteca + índices.
NO es memoria de agente.

CAPABILITY = microservicio/cápsula ejecutable.

AGENT = ejecutor temporal.

LLM = procesador cognitivo temporal.

VISUAL TWIN = sistema externo de observación.
